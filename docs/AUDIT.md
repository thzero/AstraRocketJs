## How to read the verification tags

- **CONFIRMED BY REVIEWER** means that after the slice agent raised it, the
  cited lines (and the Java, or the published data, where relevant) were
  re-read and the claim confirmed independently for this report.
- **VERIFIED** means the slice agent read the lines and confirmed the claim
  with a failure scenario, against the Java under `engine-java/src/java` (or
  the desktop handlers) for anything ported or written for the desktop to
  read. It was not re-read a second time. These are strong leads.
- **REPORTED** means the agent raised it as plausible without fully confirming
  it. Treat these as leads, not facts.
- The tag in brackets after the severity, such as `[1c-3]`, is the slice and
  the finding's position in that slice's report, in the order listed there;
  `conv-` marks the cross-cutting conventions sweep, its website docs findings
  included. Duplicates raised by more than one agent are merged into one entry
  that cites every tag. Line numbers are as of c33c935.

## 🔴 Security

### Low

- **S1** (LOW, CONFIRMED BY REVIEWER) [1b-6] `web/src/services/exports/csvCell.ts:28` (`EMBEDDED_TRIGGER`) with `web/src/services/exports/flightPathExport.ts:1504`. A formula trigger is neutralized at the start of a value and after an embedded `,`, `;` or tab, but not after CR or LF. `csvField` quotes a value holding a newline, so the app's own writers are safe; a user CSV template that leaves a field unquoted (`{{rocketName}},{{latitude}}`) writes a design name such as `x\n=HYPERLINK(...)` from a shared `.ork` as a new row whose first cell is a live formula. *Why it matters:* The injection class the escaper exists to stop, through the one path where the writer does not quote. *Fix:* Add `\r` and `\n` to the embedded separator class, or replace CR and LF with a space in the CSV escaper.
- **S2** (LOW, CONFIRMED BY REVIEWER) [1b-7] `web/src/services/exports/rocketPrintExport.ts:136`. The separate-files 3MF zip names each entry `safeFilename(b.part.name, b.part.name || 'part')`, and `safeFilename` returns its fallback when no letter or digit survives, so the fallback is the raw part name. A part named `../..` in a shared `.ork` becomes the entry `../...3mf`; a `:` or `*` fails extraction of the whole archive on Windows. The retry on line 138 already uses `'part'`. *Why it matters:* A zip-slip shaped entry relies on the extractor to refuse it. The name is the user's own part in the user's own download, hence LOW. *Fix:* Pass `'part'` as the fallback, or strip `[\\/:*?"<>|]` and leading dots from it; add a test with a separator-only name. See C21.
- **S3** (LOW, VERIFIED) [1a-9] `web/src/state/fileSlice.ts:253`. The design open path calls `file.arrayBuffer()` before any size check. `readFileText` (`decodeText.ts:54-57`) checks `assertImportSize(file.size)` first, but the zip branch caps only the declared uncompressed sizes, and a bare file is refused only after all its bytes are in memory. *Why it matters:* Picking a multi-GB file allocates all of it before the "file too large" message, or fails out of memory instead. *Fix:* `assertImportSize(file.size)` before `arrayBuffer()`, or have `loadOrk` take the `Blob` and check it.
- **S4** (LOW, REPORTED) [1a-8] `web/src/services/files/ork/passthrough.ts:286-298` (`readPassthrough`). The number of unknown children carried as raw XML per element has no cap. Each is cloned, searched for decals, serialized, stored on the node, persisted and written back on every save. `importLimits.ts` caps components and simulations because a byte cap does not bound a count. *Why it matters:* `<x/>` is 4 bytes, so one component can carry millions of entries inside the 64 MiB member cap, and the workspace store then holds millions of strings. *Fix:* A `MAX_PASSTHROUGH` ceiling per element, refusing the file past it as `tooManySimulations` does.
- **S5** (LOW, VERIFIED) [6-10] [5] `.github/workflows/deploy.yml:46, 48, 114, 116, 131`; `.github/workflows/gates.yml`; `.github/workflows/e2e-full.yml`. These workflows pin actions by mutable major tag (`checkout@v7`, `setup-node@v7`, `configure-pages@v6`, `upload-pages-artifact@v5`, `deploy-pages@v5` in deploy), while the deploy job holds `pages: write` and `id-token: write`. The R17 fix moved only `sync-catalogs.yml` to commit SHA pins. *Why it matters:* A moved tag runs new code with the token that publishes the live app. *Fix:* Pin by commit SHA with the tag in a comment, as `sync-catalogs.yml` does.
