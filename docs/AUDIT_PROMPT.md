# AUDIT_PROMPT — `web/` engineering audit (AstraRocketJs)

Paste the block below to a capable agent to (re)run the full audit. It is tailored to this repo's structure: the app lives in **`web/`** (React 18 + TypeScript + Vite + Vitest + three.js); state is a **zustand store** (`web/src/state/store.ts`) driven by an effects hook — App.tsx is tiny (~73 lines), NOT a god component; the simulation kernel is **TeaVM-compiled OpenRocket** vendored under `web/src/engine/vendor/` (do not audit it). Run from the repo root (`AstraRocketJs/`); all paths below are repo-root-relative.

---

Do a full engineering audit of the **`web/`** package in this repo (browser re-creation of OpenRocket; React 18 + TypeScript + Vite + Vitest + three.js). Cover: security, correctness bugs, bad/over-complex code, architecture, missing unit tests, dead code, linting/tooling gaps, convention drift, and accessibility.

**Method — fan out, don't read it all in one context.** Launch parallel review agents, one per slice below. Each agent reads its files fully, reports concrete findings as `SEV | CATEGORY | file:line | issue | why it matters | fix` (SEV = HIGH/MED/LOW), ranked by severity, findings-only (no preamble). Then synthesize all reports into one prioritized `docs/AUDIT.md`, grouped by category, with a "recommended order of attack" at the end.

**Slices:**

1. **File-parser / export / persistence services** — `web/src/services/{orkImport,orkExport,loadOrk,orkTree,orkTypes,engParser,thrustcurve,remoteData,motorDb,motorCombine,motorPicker,rasaeroExport,dxfExport,csvExport,schematicExport,componentExport,flightPathExport,meshExport,xmlUtil}.ts` plus the localStorage stores `web/src/services/{workspaceStore,motorStore,materialStore,templateStore,keyValueStore,settings}.ts`. These parse UNTRUSTED user files (`.ork` = zip+XML via `orkImport`; `.eng`/`.rse` motor files via `engParser`), fetch remote data (`thrustcurve`, `remoteData`, `motorDb`), and round-trip designs back out (`orkExport`, `rasaeroExport`, `dxfExport`, `csvExport`, `flightPathExport`). Hunt: **decompression bombs** (uncapped `unzipSync`/inflate on the `.ork` zip — fflate has no built-in cap), **unescaped round-trip on export** (XML injection in `orkExport`/`rasaeroExport`; CSV/formula injection `=+-@` in `csvExport`/`flightPathExport`; DXF group-code injection), `Number('')===0`/`parseFloat` accepting malformed tokens → NaN into physics, unbounded recursion on `<subcomponents>` nesting depth (stack overflow), swallowed errors (`catch {}`) producing a partial model the user thinks is complete, **untrusted `localStorage` blobs** parsed and trusted as fully typed, quota errors swallowed silently, `NaN`/`Infinity` lost through JSON round-trips, remote fetches with no timeout/size cap/shape validation, encoding/BOM assumptions.

2. **State layer** — `web/src/state/{store,useWorkspaceEffects,confirmStore,SettingsProvider}.ts(x)` + `web/src/App.tsx` + `web/src/main.tsx`. Note: unlike a god-App, business logic lives in the **store actions** and **`useWorkspaceEffects`**. Hunt: physics/business logic that belongs in a pure, tested service (the static-info build pipeline, motor matching, export field-mapping, `.ork` import wiring, per-stage report rebuild) trapped inside store actions or effects — untestable without React; **effects-as-events** (a user action serviced via effect+flag) and effects that write state derived from other state (should be a selector/computed); over-broad effect deps forcing redundant expensive engine rebuilds; the `exhaustive-deps` disables (assess each: safe or hiding a stale-closure bug); store actions that **mutate shared tree/state objects in place** (aliasing) or skip a needed clone; giant multi-purpose actions; unmemoized derived selectors re-scanning on every subscriber render; dead store state/actions.

3. **`web/src/components/**`** (excluding what slice 2 covers) — prioritize the largest/most-complex: `canvas/{Rocket3D,TreeSchematic,schematicShapes,FlightPath3D,AftView,FlightChart,FlightPathExport}`, `sim/{MotorDashboard,MotorDialog,LaunchPanel,MotorDetail,MotorRow,SimulationsPanel,SimPanel}`, `design/{PropertyPanel,ComponentTree,FreeformFinEditor,ScaleDialog,ComponentPicker,MaterialPicker}`, `layout/{SettingsDialog,AppHeader,AboutDialog,PrivacyDialog}`, `common/{NumberInput,ConfirmDialog}`, `report/ExportDialog`. Hunt: god-components; business/geometry/unit-conversion logic that belongs in a service; **missing memoization on expensive work run in the render body** (three.js scene build in Rocket3D/FlightPath3D, chart data in FlightChart, SVG scene in TreeSchematic/AftView/schematicShapes, drag/CP sweeps, mesh gen) and heavy child re-renders from inline object/array/function props; mid-async `setState` after unmount (await `file.text()`/fetch/geolocation with no mounted-guard/AbortController); **weak numeric validation** — inspect `common/NumberInput.tsx` and every caller: HTML `min=` is only a hint, so negatives/NaN can flow into geometry and the sim; `dangerouslySetInnerHTML`, unsafe `href`/`target="_blank"` without `rel="noopener"`; accessibility (pointer-only interactive SVG with `onClick` but no keyboard/role/tabIndex, `role="img"` wrapping an *interactive* SVG subtree, icon-only buttons without `aria-label`, dialogs without focus trap/restore, `div/span onClick` instead of `button`, color-only status); duplicated-and-drifted JSX (e.g. the several hand-rolled SVG charts).

4. **`web/src/tree/*.ts` + geometry services** — `web/src/tree/{shapeProfile,scaleRocket,position,cluster,assembly,tubefins,schema,nodeProps}.ts` plus `web/src/services/{solidMesh,reportGeometry,recoverySizing,reportModel,interpolate}.ts` and `web/src/components/canvas/schematicGeometry.ts`. **Important: this repo's tsconfig has `strict` + `noUnusedLocals`/`noUnusedParameters` but NOT `noUncheckedIndexedAccess`** — so `arr[i]` is typed `T` (not `T|undefined`), and out-of-bounds/empty-array indexing is unguarded by the type system. Hunt those hard, plus: divide-by-zero / NaN / Infinity from zero-dimension inputs (radius/length/count/thickness 0, identical fore/aft radius, zero-area fin → division, `sqrt` of negative, `acos`/`asin` out of [-1,1], `atan2(0,0)`); degenerate mesh (zero-area/collinear triangles, coincident vertices, inconsistent winding/normals, non-manifold output); in-place mutation of shared model/node objects; off-by-one/wrong formula in mass/CG/inertia/shoelace/interpolation/profile sampling; **duplicated-and-drifted helpers** (there are several `num()` readers and `round()`/snap helpers across `tree/` and `services/` — compare and flag divergence, esp. finiteness handling); math modules/functions with NO test coverage (name them); truly-unused modules (VERIFY by grepping `web/src` for imports before claiming dead).

5. **Dead code + tooling/conventions (whole `web/` package).** No knip/ts-prune installed — do a grep-based export-usage sweep over `web/src`; flag exports imported by nothing (or only their own `.test.ts`) and never-imported modules, but distinguish real dead code from the deliberate "exported only so a unit test can reach an internal helper" pattern (and from **side-effect imports** — `import './kernelLogSink.js'` is imported for effect, so the *module* is used even if its named exports aren't). `noUnusedLocals`/`noUnusedParameters` are ON, so focus on unused **exports** and unimported **modules** (TS won't catch those). Assess tooling: read `web/eslint.config.js`, `web/.prettierrc.json`, `web/package.json`, `web/tsconfig*.json`, and CI at `.github/workflows/{deploy-pages,sync-wiki}.yml`. Check: does CI run lint/typecheck/test as a **PR gate**, or only at deploy (the `build` script already chains `tsc --noEmit && eslint .`, and there's `format:check` + `test`)? Is `eslint .` run with `--max-warnings 0`, or do `warn`-level rules (`exhaustive-deps`, unused) never fail CI? Is `noUncheckedIndexedAccess` off (it is — recommend enabling, note the migration cost)? Does `tsconfig` exclude test files from `tsc`? Inert/pointless `eslint-disable` comments; named-vs-default export consistency; duplicated helper modules. Recommend a concrete minimal setup (knip config, `noUncheckedIndexedAccess`, a PR CI gate).

**Verification discipline — do NOT relay agent claims unchecked:**
- Independently confirm every HIGH/MED **security** finding against the actual source lines before it goes in the report (read the lines; confirm the escape/cap is genuinely absent).
- Confirm every **dead-code** claim by grepping all of `web/src` for imports (and note test-only usage) before asserting it.
- Be skeptical: only report issues with a specific `file:line` and a plausible failure scenario. No style nitpicks presented as findings.

**Codebase-specific notes — verify current state, don't blindly carry forward:**
- **`web/src/engine/vendor/`** is the TeaVM-compiled OpenRocket kernel (`openrocket-engine.mjs` + `.wasm`) — GENERATED; do NOT audit it. The audit boundary is the `@JSExport` facade wrapped by `web/src/engine/openRocketEngine.ts`.
- Browser `DOMParser` does not resolve external entities → **XXE not exploitable** in `orkImport`.
- `orkImport` mints node ids via `freshId()` (Maps/Sets), so parsed strings are not used as write keys → **no prototype-pollution write surface** — only report proto-pollution if you find an actual `obj[untrustedKey] = …` write.
- `import './kernelLogSink.js'` (in `openRocketEngine.ts`) is a **side-effect import** (installs stdout/stderr sinks); the module is used even though its named exports (`kernelLog`/`clearKernelLog`/`setKernelLogEcho`) may be unused — flag the *exports*, not the module.
- Some exports exist only so a unit test can reach an internal helper — deliberate, label "test-only export (intentional)", not dead.
- The 2D schematic (`components/canvas/{TreeSchematic,schematicShapes,schematicGeometry,AftView}`) is a simplified fork of mmrocket-sim's and its projection math was recently reworked for pods — regressions are likeliest there.
- `App` and `i18n` use default exports intentionally; the rest of the tree is named exports.
