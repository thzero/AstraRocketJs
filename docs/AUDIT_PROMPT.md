# AUDIT_PROMPT: `web/` engineering audit (AstraRocketJs)

Paste the block below to a capable agent to (re)run the full audit. It is tailored to this repo's structure: the app lives in **`web/`** (React 19 + TypeScript + Vite + Vitest + three.js); state is a **zustand store** (`web/src/state/store.ts` for the editing core, plus `viewSlice.ts`, `fileSlice.ts` and `requestStore.ts`) driven by an effects hook; App.tsx is thin (~340 lines), NOT a god component; the simulation kernel is **TeaVM-compiled OpenRocket** vendored under `web/src/engine/vendor/` (do not audit it). Run from the repo root (`AstraRocketJs/`); all paths below are repo-root-relative.

---

Do a full engineering audit of the **`web/`** package in this repo (browser re-creation of OpenRocket; React 19 + TypeScript + Vite + Vitest + three.js). Cover: security, correctness bugs, bad/over-complex code, architecture, missing unit tests, dead code, linting/tooling gaps, convention drift, and accessibility.

**Method: fan out, don't read it all in one context.** Launch parallel review agents, one per slice below. Each agent reads its files fully, reports concrete findings as `SEV | CATEGORY | file:line | issue | why it matters | fix` (SEV = HIGH/MED/LOW), ranked by severity, findings-only (no preamble). Then synthesize all reports into one prioritized `docs/AUDIT.md`, grouped by category, with a "recommended order of attack" at the end.

**Slices:**

1. **File-parser / export / persistence services**: `web/src/services/files/{orkImport,orkExport,loadOrk,orkTypes,rasaeroExport,componentExport,xmlUtil,rktImport,rktExport}.ts`, `web/src/services/files/ork/*.ts`, `web/src/services/motors/{engParser,rseParser,thrustcurve,motorDb,motorCombine,motorPicker}.ts`, `web/src/services/exports/{dxfExport,csvExport,schematicExport,flightPathExport,meshExport}.ts`, `web/src/services/design/orkTree.ts` and `web/src/services/app/remoteData.ts` plus the persistence layer `web/src/services/storage/{workspaceStore,keyValueStore,idbKeyValueStore,persistStorage,designLibrary,settings}.ts`, `web/src/services/motors/motorStore.ts`, `web/src/services/materials/materialStore.ts`, `web/src/services/exports/templateStore.ts` and `web/tests/services/storage/workspaceJournal.test.ts` and the newer output/transfer paths `web/src/services/files/{saveFile,saveOrk}.ts`, `web/src/services/report/{reportCsv,reportPdf}.ts` and `web/src/services/app/fetchProgress.ts`. These parse UNTRUSTED user files (`.ork` = zip+XML via `orkImport`; `.rkt` via `rktImport`; `.eng`/`.rse` motor files via `engParser`/`rseParser`), fetch remote data (`thrustcurve`, `remoteData`, `motorDb`), and round-trip designs back out (`orkExport`, `rasaeroExport`, `dxfExport`, `csvExport`, `flightPathExport`). Hunt: **decompression bombs** (uncapped `unzipSync`/inflate on the `.ork` zip; fflate has no built-in cap), **unescaped round-trip on export** (XML injection in `orkExport`/`rasaeroExport`; CSV/formula injection `=+-@` in `csvExport`/`flightPathExport`; DXF group-code injection), `Number('')===0`/`parseFloat` accepting malformed tokens → NaN into physics, unbounded recursion on `<subcomponents>` nesting depth (stack overflow), swallowed errors (`catch {}`) producing a partial model the user thinks is complete, **untrusted `localStorage` blobs** parsed and trusted as fully typed, quota errors swallowed silently, `NaN`/`Infinity` lost through JSON round-trips, remote fetches with no timeout/size cap/shape validation, encoding/BOM assumptions. For the IndexedDB tier specifically: unhandled `onerror`/`onblocked`, transactions that outlive an `await`, version-upgrade paths, and quota failures that leave the journal and the store disagreeing.

2. **State layer**: `web/src/state/{store,viewSlice,fileSlice,requestStore,useWorkspaceEffects,confirmStore,SettingsProvider}.ts(x)` + `web/src/App.tsx` + `web/src/main.tsx`. Note: unlike a god-App, business logic lives in the **store actions** and **`useWorkspaceEffects`**. Hunt: physics/business logic that belongs in a pure, tested service (the static-info build pipeline, motor matching, export field-mapping, `.ork` import wiring, per-stage report rebuild) trapped inside store actions or effects, untestable without React; **effects-as-events** (a user action serviced via effect+flag) and effects that write state derived from other state (should be a selector/computed); over-broad effect deps forcing redundant expensive engine rebuilds; the `exhaustive-deps` disables (assess each: safe or hiding a stale-closure bug); store actions that **mutate shared tree/state objects in place** (aliasing) or skip a needed clone; giant multi-purpose actions; unmemoized derived selectors re-scanning on every subscriber render; dead store state/actions.

3. **`web/src/components/**`** (excluding what slice 2 covers): prioritize the largest/most-complex: `canvas/{Rocket3D,TreeSchematic,schematicShapes,FlightPath3D,AftView,FlightChart,FlightPathExport,AeroAnalysis}`, `sim/{MotorDashboard,MotorDialog,LaunchPanel,MotorDetail,MotorRow,SimulationsPane,SimulationsTable,SimEditor}`, `design/{PropertyPanel,ComponentTree,FreeformFinEditor,ScaleDialog,ComponentPicker,MaterialPicker}`, `layout/{SettingsDialog,AppHeader,AboutDialog,PrivacyDialog}`, `common/{NumberInput,ConfirmDialog,UnitChip,CatalogLoading,Stat}`, `report/ExportDialog`, and the newer `canvas/{CenterView,ViewToggle}`, `sim/SimSummary`, `layout/{TabBar,UpdateToast,DesignLibraryDialog,DesignPropertiesDialog}`, `sim/MotorSpecDialog`. Hunt: god-components; business/geometry/unit-conversion logic that belongs in a service; **missing memoization on expensive work run in the render body** (three.js scene build in Rocket3D/FlightPath3D, chart data in FlightChart, SVG scene in TreeSchematic/AftView/schematicShapes, drag/CP sweeps, mesh gen) and heavy child re-renders from inline object/array/function props; mid-async `setState` after unmount (await `file.text()`/fetch/geolocation with no mounted-guard/AbortController); **weak numeric validation**: inspect `common/NumberInput.tsx` and every caller: HTML `min=` is only a hint, so negatives/NaN can flow into geometry and the sim; `dangerouslySetInnerHTML`, unsafe `href`/`target="_blank"` without `rel="noopener"`; accessibility (pointer-only interactive SVG with `onClick` but no keyboard/role/tabIndex, `role="img"` wrapping an _interactive_ SVG subtree, icon-only buttons without `aria-label`, dialogs without focus trap/restore, `div/span onClick` instead of `button`, color-only status); duplicated-and-drifted JSX (e.g. the several hand-rolled SVG charts).

4. **`web/src/tree/*.ts` + geometry services**: `web/src/tree/{shapeProfile,scaleRocket,position,cluster,assembly,tubefins,schema,nodeProps,schematicGeometry}.ts` plus `web/src/services/exports/solidMesh.ts`, `web/src/services/report/{reportGeometry,reportModel}.ts` and `web/src/services/flight/{recoverySizing,interpolate}.ts`. **Note: `noUncheckedIndexedAccess` is now ON** (the last audit recommended it; it was adopted), so `arr[i]` is `T|undefined` and the compiler catches raw out-of-bounds reads. What it does NOT catch is a `?? 0`/`!`/`as` that _silences_ the check while still feeding a wrong default into physics; hunt those, plus: divide-by-zero / NaN / Infinity from zero-dimension inputs (radius/length/count/thickness 0, identical fore/aft radius, zero-area fin → division, `sqrt` of negative, `acos`/`asin` out of [-1,1], `atan2(0,0)`); degenerate mesh (zero-area/collinear triangles, coincident vertices, inconsistent winding/normals, non-manifold output); in-place mutation of shared model/node objects; off-by-one/wrong formula in mass/CG/inertia/shoelace/interpolation/profile sampling; **duplicated-and-drifted helpers** (the `num()` readers and `round()`/snap helpers across `tree/` and `services/` were consolidated; verify they stayed consolidated and flag any new copy, esp. its finiteness handling); math modules/functions with NO test coverage (name them); truly-unused modules (VERIFY by grepping `web/src` for imports before claiming dead).

5. **Dead code + tooling/conventions (whole `web/` package).** **knip IS installed** (`web/knip.json`, `npm run knip`): run it first and treat its output as a starting point, not the answer: verify each claim by grepping `web/src`, and distinguish real dead code from the deliberate "exported only so a unit test can reach an internal helper" pattern and from **side-effect imports** (`import './kernelLogSink.js'` is imported for effect, so the _module_ is used even if its named exports aren't). `noUnusedLocals`/`noUnusedParameters`/`noUncheckedIndexedAccess` are all ON, so focus on unused **exports** and unimported **modules**.

   Tooling: read `web/eslint.config.js`, `web/.prettierrc.json`, `web/package.json`, `web/tsconfig*.json`, `web/knip.json`, `cspell.json` and CI at `.github/workflows/{ci,gates,dev,deploy,e2e-full,sync-catalogs}.yml`. The CI layout: `gates.yml` is a reusable workflow (`workflow_call`) holding the gate set, and both `ci.yml` (every pull request) and `deploy.yml` (every push to master, before the Pages publish) call it. Its jobs are `parity` (JVM vs TeaVM-JS vs WASM-GC, plus a rebuild-and-diff that the committed engine matches `src/java`), `reproducible` (`extract:check`), `validate`, `build-and-test` (`npm run verify:ci`), `e2e` (`npm run e2e:core`, the core specs) and `update-flow` (the service worker update path and offline catalogs against production builds). `npm run verify:ci` is `npm run gates` (`format:check`, `spell`, `typecheck`, `lint`, `knip`, `vite build`, with `format:check` first) followed by `test:coverage`. `dev.yml` runs `verify:ci` on every push to a branch other than master. The full e2e suite runs by hand in `e2e-full.yml`. `sync-catalogs.yml` is scheduled and refreshes the motor and component catalogs. `cspell.json` covers `web/src/i18n/locales/en.json`; the other locale files are outside the spell gate. `noUncheckedIndexedAccess` is enabled. Do not re-report any of this as open; verify and move on. Are there gates whose SCOPE excludes the thing they claim to cover? Named-vs-default export consistency; duplicated helper modules.

   Lint and accessibility tooling: ESLint runs all of typescript-eslint `recommendedTypeChecked` on `**/*.{ts,tsx}`, with `no-floating-promises` and `no-misused-promises` set explicitly. In tests (`tests/**` and `**/*.test.{ts,tsx}`) `require-await`, the `no-unsafe-*` family and `no-unnecessary-type-assertion` are off; `web/eslint.config.js` states the reason for each. `eslint-plugin-jsx-a11y-x` runs its recommended set on `src/**/*.tsx`; it is the es-tooling fork of `eslint-plugin-jsx-a11y` with the same rules, used because the original's peer range stops at ESLint 9. `web/e2e/a11y.spec.ts` runs axe (`@axe-core/playwright`, WCAG 2.0/2.1 A and AA tags) on Design, Simulations, Results and Settings in the dark, light and daylight themes, so text contrast is checked per theme, and checks that the charts describe themselves to a screen reader. Check that every `jsx-a11y-x` disable comment states its reason, that the axe scan still covers every top-level view and every theme, and that code comments state the constraint in present tense with no change history.

**Ported kernel math: check it against the Java, NEVER against another copy in `web/`.**
`web/src/tree/*` and the geometry services re-implement OpenRocket math in TypeScript. The `parity` CI job does NOT cover any of it: parity compares the kernel to ITSELF across JVM, TeaVM-JS and WASM-GC. The authoritative reference is the committed Java under `engine-java/src/java/info/openrocket/core/`. Open it and compare term by term.
This is not hypothetical: the elliptical fin planform was a sine arch instead of a half-ellipse in three of four modules from 2026-09-07 to 2026-09-19, and THREE audits missed it because each one compared the four copies to each other and took the oldest as ground truth. One audit's fix propagated the wrong curve into a new module and labeled it "A true half-ellipse".
Also distrust any test that pins a parameterized curve only by its point count, endpoints or extremum; those are exactly the properties the wrong curve shared with the right one. Demand an interior-point assertion against a closed form.
`web/tests/tree/finPlanform.kernel.test.ts` is the pattern to follow and extend for any newly-found port.
