# AUDIT_PROMPT — `web/` engineering audit (AstraRocketJs)

Paste the block below to a capable agent to (re)run the full audit. It is tailored to this repo's structure: the app lives in **`web/`** (React 18 + TypeScript + Vite + Vitest + three.js); state is a **zustand store** (`web/src/state/store.ts`) driven by an effects hook — App.tsx is tiny (~73 lines), NOT a god component; the simulation kernel is **TeaVM-compiled OpenRocket** vendored under `web/src/engine/vendor/` (do not audit it). Run from the repo root (`AstraRocketJs/`); all paths below are repo-root-relative.

---

Do a full engineering audit of the **`web/`** package in this repo (browser re-creation of OpenRocket; React 18 + TypeScript + Vite + Vitest + three.js). Cover: security, correctness bugs, bad/over-complex code, architecture, missing unit tests, dead code, linting/tooling gaps, convention drift, and accessibility.

**Method — fan out, don't read it all in one context.** Launch parallel review agents, one per slice below. Each agent reads its files fully, reports concrete findings as `SEV | CATEGORY | file:line | issue | why it matters | fix` (SEV = HIGH/MED/LOW), ranked by severity, findings-only (no preamble). Then synthesize all reports into one prioritized `docs/AUDIT.md`, grouped by category, with a "recommended order of attack" at the end.

**Slices:**

1. **File-parser / export / persistence services** — `web/src/services/{orkImport,orkExport,loadOrk,orkTree,orkTypes,engParser,thrustcurve,remoteData,motorDb,motorCombine,motorPicker,rasaeroExport,dxfExport,csvExport,schematicExport,componentExport,flightPathExport,meshExport,xmlUtil}.ts` plus the persistence layer `web/src/services/{workspaceStore,workspaceJournal,motorStore,materialStore,templateStore,keyValueStore,idbKeyValueStore,persistStorage,designLibrary,settings}.ts` and the newer output/transfer paths `web/src/services/{saveFile,saveOrk,reportCsv,reportPdf,fetchProgress}.ts`. These parse UNTRUSTED user files (`.ork` = zip+XML via `orkImport`; `.eng`/`.rse` motor files via `engParser`), fetch remote data (`thrustcurve`, `remoteData`, `motorDb`), and round-trip designs back out (`orkExport`, `rasaeroExport`, `dxfExport`, `csvExport`, `flightPathExport`). Hunt: **decompression bombs** (uncapped `unzipSync`/inflate on the `.ork` zip — fflate has no built-in cap), **unescaped round-trip on export** (XML injection in `orkExport`/`rasaeroExport`; CSV/formula injection `=+-@` in `csvExport`/`flightPathExport`; DXF group-code injection), `Number('')===0`/`parseFloat` accepting malformed tokens → NaN into physics, unbounded recursion on `<subcomponents>` nesting depth (stack overflow), swallowed errors (`catch {}`) producing a partial model the user thinks is complete, **untrusted `localStorage` blobs** parsed and trusted as fully typed, quota errors swallowed silently, `NaN`/`Infinity` lost through JSON round-trips, remote fetches with no timeout/size cap/shape validation, encoding/BOM assumptions. **Much of this slice is new or heavily rewritten since the last audit** — `idbKeyValueStore`/`persistStorage`/`workspaceJournal`/`designLibrary`/`saveFile` are new modules, and `flightPathExport` (+476 lines), `remoteData`, `rasaeroExport`, `csvExport` and `workspaceStore` were substantially reworked; weight the reading accordingly. For the IndexedDB tier specifically: unhandled `onerror`/`onblocked`, transactions that outlive an `await`, version-upgrade paths, and quota failures that leave the journal and the store disagreeing.

2. **State layer** — `web/src/state/{store,useWorkspaceEffects,confirmStore,SettingsProvider}.ts(x)` + `web/src/App.tsx` + `web/src/main.tsx`. Note: unlike a god-App, business logic lives in the **store actions** and **`useWorkspaceEffects`**. Hunt: physics/business logic that belongs in a pure, tested service (the static-info build pipeline, motor matching, export field-mapping, `.ork` import wiring, per-stage report rebuild) trapped inside store actions or effects — untestable without React; **effects-as-events** (a user action serviced via effect+flag) and effects that write state derived from other state (should be a selector/computed); over-broad effect deps forcing redundant expensive engine rebuilds; the `exhaustive-deps` disables (assess each: safe or hiding a stale-closure bug); store actions that **mutate shared tree/state objects in place** (aliasing) or skip a needed clone; giant multi-purpose actions; unmemoized derived selectors re-scanning on every subscriber render; dead store state/actions.

3. **`web/src/components/**`** (excluding what slice 2 covers) — prioritize the largest/most-complex: `canvas/{Rocket3D,TreeSchematic,schematicShapes,FlightPath3D,AftView,FlightChart,FlightPathExport,AeroAnalysis}`, `sim/{MotorDashboard,MotorDialog,LaunchPanel,MotorDetail,MotorRow,SimulationsPanel,SimPanel}`, `design/{PropertyPanel,ComponentTree,FreeformFinEditor,ScaleDialog,ComponentPicker,MaterialPicker}`, `layout/{SettingsDialog,AppHeader,AboutDialog,PrivacyDialog}`, `common/{NumberInput,ConfirmDialog,UnitChip,CatalogLoading,Stat}`, `report/ExportDialog`, and the newer `canvas/{CenterView,ViewToggle}`, `sim/SimSummary`, `layout/{TabBar,UpdateToast,DesignLibraryDialog,DesignPropertiesDialog}`, `sim/MotorSpecDialog`. **`canvas/AeroAnalysis.tsx` is brand new and the single largest component (~990 lines)** — read it in full; it holds three tables, two chart panes, a flight-conditions strip and its own cell-shading, and has never been audited. Hunt: god-components; business/geometry/unit-conversion logic that belongs in a service; **missing memoization on expensive work run in the render body** (three.js scene build in Rocket3D/FlightPath3D, chart data in FlightChart, SVG scene in TreeSchematic/AftView/schematicShapes, drag/CP sweeps, mesh gen) and heavy child re-renders from inline object/array/function props; mid-async `setState` after unmount (await `file.text()`/fetch/geolocation with no mounted-guard/AbortController); **weak numeric validation** — inspect `common/NumberInput.tsx` and every caller: HTML `min=` is only a hint, so negatives/NaN can flow into geometry and the sim; `dangerouslySetInnerHTML`, unsafe `href`/`target="_blank"` without `rel="noopener"`; accessibility (pointer-only interactive SVG with `onClick` but no keyboard/role/tabIndex, `role="img"` wrapping an *interactive* SVG subtree, icon-only buttons without `aria-label`, dialogs without focus trap/restore, `div/span onClick` instead of `button`, color-only status); duplicated-and-drifted JSX (e.g. the several hand-rolled SVG charts).

4. **`web/src/tree/*.ts` + geometry services** — `web/src/tree/{shapeProfile,scaleRocket,position,cluster,assembly,tubefins,schema,nodeProps}.ts` plus `web/src/services/{solidMesh,reportGeometry,recoverySizing,reportModel,interpolate}.ts` and `web/src/components/canvas/schematicGeometry.ts`. **Note: `noUncheckedIndexedAccess` is now ON** (the last audit recommended it; it was adopted), so `arr[i]` is `T|undefined` and the compiler catches raw out-of-bounds reads. What it does NOT catch is a `?? 0`/`!`/`as` that *silences* the check while still feeding a wrong default into physics — hunt those, plus: divide-by-zero / NaN / Infinity from zero-dimension inputs (radius/length/count/thickness 0, identical fore/aft radius, zero-area fin → division, `sqrt` of negative, `acos`/`asin` out of [-1,1], `atan2(0,0)`); degenerate mesh (zero-area/collinear triangles, coincident vertices, inconsistent winding/normals, non-manifold output); in-place mutation of shared model/node objects; off-by-one/wrong formula in mass/CG/inertia/shoelace/interpolation/profile sampling; **duplicated-and-drifted helpers** (there are several `num()` readers and `round()`/snap helpers across `tree/` and `services/` — compare and flag divergence, esp. finiteness handling); math modules/functions with NO test coverage (name them); truly-unused modules (VERIFY by grepping `web/src` for imports before claiming dead).

5. **Dead code + tooling/conventions (whole `web/` package).** **knip IS installed** (`web/knip.json`, `npm run knip`) — run it first and treat its output as a starting point, not the answer: verify each claim by grepping `web/src`, and distinguish real dead code from the deliberate "exported only so a unit test can reach an internal helper" pattern and from **side-effect imports** (`import './kernelLogSink.js'` is imported for effect, so the *module* is used even if its named exports aren't). Note knip's `entry` lists `src/**/*.test.ts` but **not** `*.test.tsx` — check whether that blinds it to anything. `noUnusedLocals`/`noUnusedParameters`/`noUncheckedIndexedAccess` are all ON, so focus on unused **exports** and unimported **modules**.

   Tooling: read `web/eslint.config.js`, `web/.prettierrc.json`, `web/package.json`, `web/tsconfig*.json`, `web/knip.json` and CI at `.github/workflows/{ci,deploy-pages,sync-catalogs}.yml`. **The previous audit's tooling gaps are all closed** — `ci.yml` is a PR gate running `npm run test` + `npm run build` (which chains `tsc --noEmit && eslint . --max-warnings 0 && vite build`), and `noUncheckedIndexedAccess` is enabled. So the open questions are the *remaining* holes: `format:check`, `knip` and the Playwright `e2e` suite are **not** run by any workflow — is that deliberate or drift? Does anything gate the `engine-java/` JVM↔WASM parity harness? Are there `eslint-disable` comments that are now inert? Named-vs-default export consistency; duplicated helper modules. Also flag **pre-existing `prettier --check` drift** in tracked files (e.g. `web/src/i18n/locales/es.json`) — it means `format:check` cannot be added to CI until it is cleared.

**Verification discipline — do NOT relay agent claims unchecked:**
- Independently confirm every HIGH/MED **security** finding against the actual source lines before it goes in the report (read the lines; confirm the escape/cap is genuinely absent).
- Confirm every **dead-code** claim by grepping all of `web/src` for imports (and note test-only usage) before asserting it.
- Be skeptical: only report issues with a specific `file:line` and a plausible failure scenario. No style nitpicks presented as findings.

**Codebase-specific notes — verify current state, don't blindly carry forward:**
- **`web/src/engine/vendor/`** is the TeaVM-compiled OpenRocket kernel (`openrocket-engine.mjs` + `.wasm`) — GENERATED; do NOT audit it. The audit boundary is the `@JSExport` facade wrapped by `web/src/engine/openRocketEngine.ts`.
- Browser `DOMParser` does not resolve external entities → **XXE not exploitable** in `orkImport`.
- `orkImport` mints node ids via `freshId()` (Maps/Sets), so parsed strings are not used as write keys → **no prototype-pollution write surface** — only report proto-pollution if you find an actual `obj[untrustedKey] = …` write.
- `import './kernelLogSink.js'` (in `openRocketEngine.ts`) is a **side-effect import** (installs stdout/stderr sinks); the module is used even though its named exports (`kernelLog`/`clearKernelLog`/`setKernelLogEcho`) may be unused — flag the *exports*, not the module.
- Some exports exist only so a unit test can reach an internal helper — deliberate, label "test-only export (intentional)", not dead.
- The 2D schematic (`components/canvas/{TreeSchematic,schematicShapes,schematicGeometry,AftView}`) is a simplified fork of mmrocket-sim's and its projection math was recently reworked for pods — regressions are likeliest there.
- `App` and `i18n` use default exports intentionally; the rest of the tree is named exports.
