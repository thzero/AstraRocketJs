# AUDIT_PROMPT: `web/` engineering audit (AstraRocketJs)

Paste the block below to a capable agent to (re)run the full audit. It is tailored to this repo's structure: the app lives in **`web/`** (React 19 + TypeScript + Vite + Vitest + three.js); state is a **zustand store** (`web/src/state/store.ts` for the editing core, plus `viewSlice.ts`, `fileSlice.ts`, `workspaceSelectors.ts` and the smaller stores beside them) driven by an effects hook; App.tsx is thin (~350 lines), NOT a god component; the simulation kernel is **TeaVM-compiled OpenRocket** vendored under `web/src/engine/vendor/` (do not audit it). Run from the repo root (`AstraRocketJs/`); all paths below are repo-root-relative.

---

Do a full engineering audit of the **`web/`** package in this repo (browser re-creation of OpenRocket; React 19 + TypeScript + Vite + Vitest + three.js). Cover: security, correctness bugs, gates that pass while their subject is broken, accessibility failures, the reference data the app ships and publishes, and upkeep (comments, test names, duplicated helpers, docs). Apply the reporting bar below to every slice.

**Method: fan out, don't read it all in one context.** Launch parallel review agents, one per slice below. Each agent reads every file in its slice fully, reports concrete findings as `SEV | CATEGORY | file:line | issue | why it matters | fix` (SEV = HIGH/MED/LOW), ranked by severity, findings-only (no preamble), each marked VERIFIED (it read the lines and confirmed the claim) or REPORTED (plausible, not fully confirmed), and ends with the number of files it read. Then synthesize all reports into one prioritized `docs/AUDIT.md`, grouped by category, with a "recommended order of attack" at the end.

**Slices.** Defined by folder, so a new file is in a slice the day it is added. A slice that is too large for one agent is split by subfolder, never trimmed to a list of files.

1. **Files, exports, persistence and remote data**: `web/src/services/{files,exports,storage,motors,materials,report}/**`, `web/src/services/app/**` and `web/src/services/design/orkTree.ts`. These parse UNTRUSTED user files (`.ork` = zip+XML via `orkImport`; `.rkt` via `rktImport`; `.eng`/`.rse` motor files), fetch remote data, and round-trip designs back out. Hunt: **decompression bombs** and uncapped reads (fflate has no built-in cap; every reader of a user file has to cap its size before decoding), **unescaped round-trip on export** (XML injection; CSV/formula injection `=+-@` in every CSV writer, comment and title lines included; KML balloon HTML; DXF group-code injection), `Number('')===0`/`parseFloat` accepting malformed tokens → NaN into physics, unbounded recursion on nesting depth, swallowed errors producing a partial model the user thinks is complete, **untrusted stored blobs** parsed and trusted as fully typed, quota errors swallowed, `NaN`/`Infinity` lost through JSON round-trips, remote fetches with no timeout, size cap or shape validation, encoding/BOM assumptions. For the IndexedDB tier: unhandled `onerror`/`onblocked`, transactions that outlive an `await`, version-upgrade paths, quota failures that leave the journal and the store disagreeing, and two tabs writing the same design. File handlers are checked against the desktop's own (`RocketComponentSaver`, the importer handlers, the RockSim handlers, all under `engine-java/.openrocket-src/core/src/main/java/info/openrocket/core/file/`, which the extractor checks out at the upstream `unstable` commit and which can differ from 24.12, so settle desktop's behavior with `javap` on the release jar or with `check:ork` and `check:fields`; the extracted kernel has no file handlers), not against the element names. `npm run audit` opens what the writers emit in desktop 24.12 and reads every part back (the `fields` step), and its `KNOWN` list names the writer differences still open; report each under this run's ID (see "A `KNOWN` entry is an open defect") and audit what the step does not compare.

2. **State, engine wrapper, units and locales**: `web/src/state/**`, `web/src/engine/**` except `vendor/`, `web/src/prefs/**`, `web/src/i18n/**` (the code; the locale JSON is read for keys, not prose), and the root files `web/src/App.tsx`, `web/src/main.tsx`, `web/src/index.css`, `web/src/globals.d.ts` and `web/src/vite-env.d.ts`. Business logic lives in the **store actions** and **`useWorkspaceEffects`**. In the engine wrapper, hunt: a worker pool that loses or double-delivers a reply when a worker dies or a run is canceled, protocol messages whose shape is trusted without a check, an init that cannot be retried after a failed load (and a retry that reuses the same URL, which the browser coalesces), and a backend choice that never falls back. In prefs and i18n, hunt: unit conversions that round-trip with drift or apply an offset unit (temperature) as a scale, number formatting that ignores the locale or prints `NaN`, a parse that accepts the wrong decimal separator, and locale loading that races the first render or leaves a key untranslated on a failed fetch. In the state layer, hunt: physics or business logic trapped in store actions or effects that belongs in a pure, tested service; **effects-as-events** and effects that write state derived from other state; over-broad effect deps forcing redundant engine rebuilds; `exhaustive-deps` disables (assess each); actions that **mutate shared tree/state objects in place**; actions that record an undo step and then change nothing; async actions that resolve on failure so their callers cannot tell; an action started again while its previous call is still running; autosave or persistence triggered by loading rather than editing; dead store state/actions.

3. **Components**, split in two agents: **3a** `web/src/components/canvas/**`, **3b** the rest of `web/src/components/**`. Hunt: god-components; business, geometry or unit-conversion logic that belongs in a service; **missing memoization on expensive render work** (three.js scene builds, chart data, SVG scenes, sweeps, mesh generation) and heavy child re-renders from inline props; mid-async `setState` after unmount; **weak numeric validation** (HTML `min=` is only a hint; check every `NumberInput` caller and every clamp against the kernel's own setter clamps); `dangerouslySetInnerHTML`, unsafe `href`/`target="_blank"`; **inert controls** (anything that looks clickable and does nothing, including pointer events disabled by a parent); accessibility (pointer-only SVG interaction, icon-only buttons without a name, dialogs without focus trap/restore, `div onClick` instead of `button`, status shown by color alone, live regions that never speak or that flood on pointer moves); user-facing literals that bypass i18n; duplicated-and-drifted JSX.

4. **Tree and geometry**: `web/src/tree/**`, `web/src/services/exports/solidMesh.ts`, `web/src/services/report/{reportGeometry,reportModel}.ts`. `noUncheckedIndexedAccess` is ON, so hunt the `?? 0`/`!`/`as` that silences it while feeding a wrong default into physics; divide-by-zero / NaN / Infinity from zero dimensions; degenerate meshes; in-place mutation of shared nodes; wrong formulas in mass/CG/inertia/profile sampling; **duplicated-and-drifted helpers** (the `num()` readers and `round()`/snap helpers were consolidated; flag any new copy); math with no test coverage; truly-unused modules (grep before claiming).

   **4b. Flight and design services**, its own agent: `web/src/services/{flight,design,parts,landing,tools,weather,map}/**`. This is where the app resolves geometry for itself before the kernel sees a design (automatic radii, bores, shoulders, catalog parts) and where it reads flight results back (events, recovery, wind, safety limits). Check every rule against the Java (see "Ported kernel math" below) and every flight reading against what the kernel records. This slice found three of the five HIGH findings on 2026-10-09; do not fold it into slice 4.

5. **Dead code and tooling (whole `web/` package).** **knip IS installed** (`web/knip.json`, `npm run knip`): run it first and treat its output as a starting point; verify each claim by grepping `web/src`, and distinguish real dead code from the deliberate "exported only so a unit test can reach an internal helper" pattern and from **side-effect imports**. `noUnusedLocals`/`noUnusedParameters`/`noUncheckedIndexedAccess` are ON, so focus on unused **exports** and unimported **modules**.

   Tooling: read `web/eslint.config.js`, `web/.prettierrc.json`, `web/package.json`, `web/tsconfig*.json`, `web/knip.json`, `web/.jscpd.json`, `cspell.json` and CI at `.github/workflows/{ci,gates,dev,deploy,e2e-full,sync-catalogs}.yml`. The CI layout: `gates.yml` is a reusable workflow (`workflow_call`) holding the gate set, and `ci.yml` (every pull request) and `dev.yml` (every push to a branch other than master) call it; `deploy.yml` builds and publishes on every push to master and runs no gates. Its jobs are `build-and-test` (`npm run verify`, no coverage), `e2e` (`npm run e2e:core`, the core specs, and the `website/` typecheck) and `update-flow` (the service worker against production builds: it builds the docs site, then runs `npm run e2e:update` for the update path, `npm run e2e:offline-data` for the catalogs with the network off, and `npm run e2e:offline-help` for the Help dialog with the network off). `dev.yml` calls it on every push to a branch other than master and adds a `verify` job that fails if any gate failed (branch protection requires `Dev / verify`). `npm run verify` is `npm run gates` (`format:check`, `spell`, `typecheck`, `lint`, `knip`, `dupes`, `vite build`, with `format:check` first) followed by `vitest run`. CI runs no engine checks, no coverage and no desktop file check: run `npm run audit` in `engine-java` and `npm run audit` in `web` for every audit, and report a failing step as a finding. The full e2e suite runs by hand in `e2e-full.yml`. `sync-catalogs.yml` is scheduled (see slice 6). `cspell.json` covers `web/src/i18n/locales/en.json`; the other locale files are outside the spell gate, so check them for garbled characters and English left untranslated. `prettier`, `cspell` and `jscpd` are exact pins on purpose (`docs/DEPENDENCIES.md`, rule 5). Do not re-report any of this as open; verify and move on. Are there gates whose SCOPE excludes the thing they claim to cover? Named-vs-default export consistency; duplicated helper modules.

   Lint and accessibility tooling: ESLint runs all of typescript-eslint `recommendedTypeChecked` on `**/*.{ts,tsx}`, with `no-floating-promises` and `no-misused-promises` set explicitly. In tests (`tests/**` and `**/*.test.{ts,tsx}`) `require-await`, the `no-unsafe-*` family and `no-unnecessary-type-assertion` are off; `web/eslint.config.js` states the reason for each. `eslint-plugin-jsx-a11y-x` runs its recommended set on `src/**/*.tsx`; it is the es-tooling fork of `eslint-plugin-jsx-a11y` with the same rules, used because the original's peer range stops at ESLint 9. `web/e2e/a11y.spec.ts` runs axe (`@axe-core/playwright`, WCAG 2.0/2.1 A and AA tags) in the dark, light and daylight themes on Design (2D, 3D and Aero), Configurations, Simulations, Results (Flight, 3D path, Ground track and Environment), Tools and Settings, and checks that the charts describe themselves to a screen reader. Every dialog (`e2e/dialogSurfaces.ts`) and every disclosure or popup (`e2e/popupSurfaces.ts`, each scanned in the state the page does not open in) is listed, and a unit test holds each list to `src`. Check that every `jsx-a11y-x` disable comment states its reason, that the axe scan still covers every top-level view, every alternate view and every theme (a view added since is a finding until it is scanned), and that code comments state the constraint in present tense with no change history. A vitest gate test (`web/tests/noEmDash.test.ts`) rejects the U+2014 character; check that the files it scans cover every place the house rule applies, and do not re-report a U+2014 it already fails on.

6. **Reference data and its pipeline**: `web/scripts/**` (the `sync-*.mjs` scripts, `scripts/lib/*`, `scripts/preset-digests/PresetDump.java`), `web/public/data/*`, and `.github/workflows/sync-catalogs.yml`. The deployed app reads its catalogs from the orphan `data` branch through jsDelivr (`VITE_DATA_BASE` in `deploy.yml`) and falls back to `web/public/data`, so **the published copy is what users get**: fetch it (`https://raw.githubusercontent.com/<repo>/data/components.generated.json` and the manifest) and compare it with the committed copy and with what the workflow would produce. A workflow that runs green while publishing a stale or incomplete catalog is a HIGH finding; a published parts catalog without digests means every saved `.ork` drops its part links, and a motor catalog without digests leaves desktop OpenRocket picking among motors that share a name. Hunt: a step the local refresh runs that the workflow does not, or the reverse; a third-party input that floats instead of being pinned (the database ref, the OpenRocket jar and its SHA-256); a refresh that changes the manifest hash when no data changed (every browser downloads the catalog again); a step that writes a catalog without refreshing the manifest, or writes it indented (the files are downloaded and cached offline); and every place the catalog's data differs from what desktop OpenRocket's library holds. The parts catalog has to match the desktop library built from the same release: the parts database OpenRocket builds from (`openrocket/openrocket-database`, at the commit OpenRocket's own `core/resources-src/datafiles/openrocket-database` submodule pins; a pin on another copy of it is a finding) plus the files OpenRocket ships in its jar (`datafiles/components/internal`); parts that share a part number kept as separate rows; each row's digest matched on type, manufacturer, part number and description; materials looked up in the part's own file first; a stated mass applied the way `ComponentPresetFactory` and each component's `loadFromPreset` apply it. Compare the catalog's row count per type with what `PresetDump` reports for that release.

**Ported kernel math: check it against the Java, NEVER against another copy in `web/`.**
`web/src/tree/*` and the services in slices 4 and 4b re-implement OpenRocket math in TypeScript. The parity check (`npm run parity` in `engine-java`) does NOT cover any of it: parity compares the kernel to ITSELF across JVM, TeaVM-JS and WASM-GC. The authoritative reference is the committed Java under `engine-java/src/java/info/openrocket/core/`. Open it and compare term by term.
This is not hypothetical. The elliptical fin planform was a sine arch instead of a half-ellipse in three of four modules from 2026-09-07 to 2026-09-19, and THREE audits missed it because each one compared the four copies to each other and took the oldest as ground truth. On 2026-10-09 the automatic radius rules had five defects against `BodyTube` and `Transition` (a stored tube fin radius never re-resolved, a 12 mm fallback where the kernel uses 25 mm, no chaining through automatic tubes, no stage crossing, flipped nose cones ignored everywhere), and the earlier audits had passed the same code.
**A test is not evidence when it pins the app's own number.** The 12 mm fallback survived because its test asserted `KERNEL_DEFAULTS.bodytube.outerRadius`, the value under test. A test of ported math takes its expected value from the kernel (built through the bridge) or from a closed form written out from the Java, never from an app constant or a hand-typed number. Also distrust any test that pins a parameterized curve only by its point count, endpoints or extremum; demand an interior-point assertion.
**The mechanical checks.** `web/tests/services/design/geometryParity.kernel.test.ts` builds 200 generated designs in the kernel and compares every automatic radius, bore, nose cone or transition profile and fin tab limit with the kernel's own (`getComponentGeometry` on the bridge), and requires the pre-run check to let each design fly. `web/tests/tree/geometryFlags.test.ts` toggles each flag that changes a part's shape (`flipped`, `filled`, `clipped`) and requires every reader (station radius, schematic, report side view, PDF template, printable solid, 3D view) to react, or to be listed in its `UNAFFECTED` table with the reason it cannot. `web/tests/services/parts/catalogPatch.kernel.test.ts` requires every catalog part that states a mass to fly within 0.5% of it. The first two keep a `KNOWN` list of accepted failures; both lists are empty. Finding IDs are numbered per audit run and `docs/AUDIT.md` is replaced each run, so a `KNOWN` entry cites an ID in the current `docs/AUDIT.md` or states its reason in words, and a new disagreement is either fixed or listed that way. `web/tests/engine/fieldReadback.kernel.test.ts` holds every field the Design tab edits to the kernel: the value the panel shows (`services/design/fieldRange.fieldValue`) has to be the value the kernel holds after the build (`getComponentFields` on the bridge, read through each part's own getters in `engine-java/src/api/java/api/ComponentFields.java`), for the part as the editor creates it, with each key left out, at each end of the range the panel allows (`fieldRange`), and on Auto. `web/scripts/check-desktop-fields.mjs` (`npm run check:fields`, the `fields` step of `npm run audit`) opens every `.ork` and `.rkt` the samples step saves, including a design with every part type, in desktop 24.12 and requires each part to come back at the same place and depth in the tree with what the app's kernel flies, overrides, materials and finish included, through the same getters; values a RockSim file restates are compared as desktop reads them. The `desktop` step keeps a list of the loader warnings that are open findings. Each list is checked both ways, and each entry matches only the difference its finding describes. A new app-side copy of kernel geometry, a new shape flag, a new reader, a new field or a new catalog field is a finding until it is added to these tests. Do not re-read what they already cover; read their generators and tables and audit what is missing from them (a part type the generator never builds, a flag combination it never sets).
`web/tests/tree/finPlanform.kernel.test.ts` is the pattern for a new closed-form port.
**The bridge is part of the port.** `engine-java/src/api/java/api/ComponentFactory.java` turns the app's node fields into kernel calls, and the app's meaning of a field has to be the one the bridge applies. A flipped nose cone's automatic base was set on its tip there until 2026-10-09; the geometry test found it only because the kernel's answer disagreed with the app's. Read the bridge's handling of every field the slice touches.
**Which OpenRocket.** The kernel is upstream `unstable` at the commit in `engine-java/extract/UPSTREAM`, newer than the desktop release most people run (24.12). Physics and geometry follow the kernel the app ships. File formats and part digests follow the desktop release, because that is what reads the files. Where the two builds disagree (a catalog part's volume since upstream 90a57aa33), a value derived from one must not be flown in the other.

**Fixes: a fix is not done until a test that does not trust it fails without it.** A test that takes its expected value from the fix passes whether the fix is right or wrong. So every fix for a finding:

- ships with a test whose expected value comes from outside the code under test: the kernel through the bridge (`getComponentFields`, `getComponentGeometry`, `getComponentInfo`), a closed form written out from the Java with its file and line, or desktop through `npm run check:fields`. Never an app constant, a value the fix computes, or a hand-typed number;
- fails on the code before the fix. Check it in a scratch copy, never by reverting the working tree: `git archive <base> web | tar -x -C <scratch>` (the base is `HEAD` for a fix not yet committed), copy the new or changed test files into the copy, run `npm install` in it (a real install, never a junction or link to `web/node_modules`), and run the test there with `npx vitest run <test>`;
- removes the `KNOWN` entries it closes in the same change (the lists are checked both ways, so a stale entry fails);
- states in the finding's resolution which test pins it.

Every change, fixes included, then goes through the change audit in `docs/AUDIT_PROMPT_CHANGES.md` before it is called done.

**A `KNOWN` entry is an open defect, not a settled one.** The entries in `fieldReadback.kernel.test.ts` and `check-desktop-fields.mjs` cite findings by ID, and a full audit replaces `docs/AUDIT.md` and numbers its findings afresh. So a full audit reports every open defect a `KNOWN` entry names, under its new ID, and rewrites each entry's citation to that ID in the same pass. An entry whose reason is a format limit stated in words (what RockSim cannot carry) stays as it is.

**Verification discipline: do NOT relay agent claims unchecked:**

- Independently confirm every HIGH finding, and every HIGH/MED **security** finding, against the actual source lines (and the Java, for a port) before it goes in the report.
- Confirm every **dead-code** claim by grepping all of `web/src` for imports (and note test-only usage) before asserting it.
- Re-resolve every citation by content; agents misquote line numbers.
- Be skeptical: only report issues with a specific `file:line` and a plausible failure scenario. No style nitpicks presented as findings.

**Reporting bar: a finding is something a user, a saved file or a published catalog would get wrong.**

- HIGH and MED: wrong numbers, lost or overwritten work, a file desktop OpenRocket reads differently, a control that fails, a security hole, a gate that passes while its subject is broken.
- LOW is reported only for security and correctness: a real failure that is rare or cheap to recover from.
- A run that finds nothing at MED or above says so. A short report is the goal, not a failure.
- Merge duplicates raised by more than one agent into one entry.

**Upkeep: reported in its own section, after the defects, never mixed into their counts.** These do not change a result today, but they mislead the next reader or let two copies drift into a defect:

- a comment that states something untrue or out of date;
- a comment or test title that narrates history, cites a ticket, an audit ID, a date or a person (the comment-history gate catches the mechanical cases; report what it misses and say so, since that is a gap in the gate);
- a duplicated helper, formula or list (the duplicate-code gate catches copies above its size floor; report smaller copies that have already drifted);
- user docs that state something the app does not do, or that name a label the app does not show.

Group upkeep by rule, one entry per rule with every site listed, not one entry per site. Upkeep entries carry no severity. Not reported anywhere: spelling, em dashes and lint the gates already enforce, refactors with no drift, performance without a measured user-visible cost, and missing tests for code that is correct.

**Codebase-specific notes: verify current state, don't blindly carry forward:**

- **`web/src/engine/vendor/`** is the TeaVM-compiled OpenRocket kernel (`openrocket-engine.mjs` + `.wasm`), GENERATED; do NOT audit it. The audit boundary is the `@JSExport` facade wrapped by `web/src/engine/openRocketEngine.ts`; the facade itself is audited by `docs/AUDIT_PROMPT_ENGINE.md`.
- Browser `DOMParser` does not resolve external entities → **XXE not exploitable** in `orkImport`.
- `orkImport` mints node ids via `freshId()` (Maps/Sets), so parsed strings are not used as write keys → **no prototype-pollution write surface**; only report proto-pollution if you find an actual `obj[untrustedKey] = …` write.
- `import './kernelLogSink.js'` (in `openRocketEngine.ts`) is a **side-effect import**; the module has no exports.
- Some exports exist only so a unit test can reach an internal helper; deliberate, label "test-only export (intentional)", not dead.
- **Fin planform geometry is centralized** in `web/src/tree/finPlanform.ts`. No consumer may sample a fin outline itself. A guard test fails on kernel trigonometry outside `tree/{finPlanform,tubefins,shapeProfile}.ts`.
- **A cone's end radii come from `tree/shapeProfile.profileEnds`**, which knows a flipped nose cone is a tail cone. A reader that takes `aftRadius` as the base end itself is a finding.
- **Fin sets on tapered parents:** freeform fin sets mount on transitions and nose cones (`Transition.isCompatible`, `engine-java/src/java/info/openrocket/core/rocketcomponent/Transition.java:910-917`, and `treeEdit.ts canHost` offers them), so the fin tab clamp uses the body radius at the tab's own stations, not one radius for the whole parent. Check every fin reader for that case.
- **Kernel behavior that is not a defect:** two automatic ends that each follow the other resolve to -1 in the kernel, as on desktop; an end that follows a flipped cone's tip, or a ring placed where its parent has no bore, resolves to 0, and the pre-run check then reports the zero.
- **`web/scripts/lib/presetVolume.mjs` repeats `catalogPatch`'s geometry on purpose** (a data script cannot import the TypeScript); `catalogPatch.kernel.test.ts` fails if the two drift.
- **Import notes are keyed** (`web/src/services/files/importNote.ts`): an importer that builds an English sentence for the banner is a finding. A plain-string note is final text, kept for workspaces saved before notes were keyed.
- `App` and `i18n` use default exports intentionally; the rest of the tree is named exports.
- **The maps use Esri's legacy tile URLs with no key, and cache tiles offline, by the owner's decision.** Not a finding: do not report the tile provider's terms, keys or offline caching.

**House rules that are findings when broken:** the OpenRocket desktop UI and file handlers are the spec, and the kernel owns the physics (an app-side estimate is allowed only if it says it is one and defers to kernel figures after a run); no inert controls; text a user reads comes from i18n. New fin fillets default to West System Six10 epoxy on purpose. RASAero is export-only. Spelling and em dashes are left to the gates (`spell`, `noEmDash.test.ts`). `web/tests/commentsStateTheConstraint.test.ts` fails on issue and PR tags, audit finding IDs, ISO dates and a short list of history phrases in comments and test titles; do not re-report what it already fails on. Comment accuracy, history in comments and test titles, duplicated helpers and docs accuracy go in the upkeep section; the slice agents report them for their own files, and there is no separate conventions sweep.

**Output:** overwrite `docs/AUDIT.md`. Severity emojis (🔴 security / 🟠 architecture+tooling / 🟡 correctness+tests+a11y / 🟢 dead code). Put the upkeep section after the defect categories. End with a stepwise "recommended order of attack" that front-loads small verified fixes and defers large refactors. Date-stamp it.
